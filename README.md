# station-analytics

Measurement-system analytics for multi-station production test data, built on a
synthetic multi-station production test line. The pipeline ingests messy test-station
measurement batches into a small SQLite warehouse, runs measurement systems analysis
(Gauge R&R, Cp/Cpk/Pp/Ppk, X-bar/R and I-MR charts, EWMA and CUSUM drift detection,
change-point estimation, station-to-station agreement), keeps a calibration register
with due and overdue alerts, and renders a self-contained HTML report. A regression gate
(`demo --check`) proves that every fault injected into the synthetic data was recovered
and that the report numbers reconcile with direct SQL.

## Status, honestly

This is an AI-assisted educational prototype built with Claude Code. All data is
synthetic and generated by `station_analytics/generate.py` from a fixed seed. There is no
production deployment, no real instrument, no real product and no real site behind it.
The optics vocabulary (luminance, colour difference, MTF50, binocular misalignment) is
used to make the example concrete; no optics expertise is claimed and the spec limits
are made up. Treat the statistics as textbook implementations that are tested against
hand-computed examples, not as validated metrology software.

## How to run

```
pip install -r requirements.txt
python -m pytest -q                              # 61 tests, fully offline, about 5 seconds
python -m station_analytics demo --check        # whole pipeline into output/, exits 1 on any failed check
```

Individual steps (defaults shown):

```
python -m station_analytics generate --out data/generated --seed 42 --days 90 [--rows 200000]
python -m station_analytics ingest   --data data/generated --db output/warehouse.sqlite
python -m station_analytics analyze  --db output/warehouse.sqlite --out output/analysis
python -m station_analytics alerts   --analysis output/analysis --instruments data/instruments.csv [--as-of 2026-04-04] [--due-within 30]
python -m station_analytics report   --analysis output/analysis --alerts output/alerts.json --out output/report.html
```

`--rows` is the approximate number of measurement values to produce (default about
200,000 from 90 days, 12 stations, 45 units per station-day and 4 metrics). `--days`
scales the horizon; the injected event days scale with it. The demo gate is calibrated
for 30 days or more, because shorter horizons leave too few baseline days for the
charts to be meaningful.

## Injected faults and how each one is caught

| Fault (from `generate.py`) | Where it is caught | Gate check |
| --- | --- | --- |
| Station spellings `STA-07`, `sta07`, `Station 7 `, `STA_07`, `STA-7`, ` sta-07` on 12% of rows | `canonical_station()` at ingest; unparseable names quarantine the row | per-station fact counts equal the generator's expected counts; zero station quarantines |
| v1 batches name the column `lum_nits`; v2 batches use `luminance_nits` | explicit rename map in the v1 `SchemaContract` | v1 values stored under `luminance_nits`, none under `lum_nits` |
| v2 batches add an undeclared `fixture_temp_c` column | `_check_columns()` quarantines the column name and its values, keeps the rows | one `unknown_column` quarantine record per v2 batch |
| 0.5% exact duplicate rows | `DataFrame.duplicated(keep="first")`, duplicates quarantined | quarantined count equals injected count; no duplicate groups in `fact_measurement` |
| Sentinels -999 and 9999, impossible values (negative luminance, dE 500, MTF 2.5, negative misalignment), `ERR` strings | per-value checks after reshaping to long format | quarantine counts by reason equal the injected cell counts |
| Missing operator (3%) and instrument serial (2%) | rows kept, `quality_flags` set, blank stored as NULL | tested in `tests/test_ingest.py` and `tests/test_pipeline.py` |
| Linear drift on STA-04 luminance from day 50 (20 nits by day 90) | daily means, CUSUM and EWMA alarm, hinge fit beats step fit | flagged as `drift`, onset within 10 days of day 50 |
| Mean shift of -0.03 on STA-08 MTF50 from day 60 | CUSUM and EWMA alarm, least-squares split | flagged as `shift`, change day within 3 days of day 60 |
| Per-station bias offsets on five station/metric pairs | station-to-station agreement on golden units (bias, limits of agreement) | reported in `agreement.csv`; not gated |

The gate also checks that no other series was flagged, that `metrics.json`, the
capability means and the report HTML match direct SQL, and that re-running the ingest
skips every batch without changing the fact table.

## Warehouse schema (SQLite)

- `dim_site(site_key, site_name, site_type)`
- `dim_station(station_key, site_key, is_reference)`
- `dim_instrument(instrument_id, station_key, serial, model)`
- `dim_unit(unit_id, unit_type, first_seen)`
- `fact_measurement(measurement_id, batch_id, station_key, unit_id, metric, value, measured_at, operator, instrument_serial, repeat_no, study, source_version, quality_flags)` with an index on `(station_key, metric, measured_at)`. `study` is `production`, `grr` or `xstation`.
- `quarantine(quarantine_id, batch_id, reason, detail, payload)` where payload is the rejected row, value or column as JSON
- `ingest_log(batch_id, source_version, rows_in, accepted, quarantined, loaded_at)`; `rows_in` counts wide source rows, `accepted` counts long measurement rows, `quarantined` counts quarantine records
- `schema_versions(source_version, contract, registered_at)`

## Formulas

Gauge R&R (ANOVA method, crossed parts x operators with repeats, interaction kept):
`SS_part = k r sum(ybar_i - ybar)^2`, `SS_operator = n r sum(ybar_j - ybar)^2`,
`SS_interaction = r sum(ybar_ij - ybar_i - ybar_j + ybar)^2`, `SS_repeat = sum(y_ijk - ybar_ij)^2`.
Variance components: repeatability = MS_repeat, interaction = (MS_inter - MS_repeat)/r,
operator = (MS_oper - MS_inter)/(n r), part = (MS_part - MS_inter)/(k r), negatives clipped
to zero. %GRR of total variation = 100 sigma_GRR / sigma_total; %GRR of tolerance =
100 x 6 sigma_GRR / (USL - LSL); number of distinct categories = floor(1.41 sigma_part / sigma_GRR).

Capability: `Cp = (USL - LSL) / (6 sigma_within)`, `Cpk = min(USL - mean, mean - LSL) / (3 sigma_within)`
with `sigma_within = Rbar / d2` over consecutive subgroups of 5 in time order. `Pp` and
`Ppk` use the overall sample standard deviation instead.

Control charts: X-bar limits `xbarbar +/- A2 Rbar`, R limits `D4 Rbar` and `D3 Rbar`;
individuals limits `xbar +/- 2.66 MRbar`, moving range UCL `3.267 MRbar`.

EWMA: `z_i = lambda x_i + (1 - lambda) z_{i-1}` with `z_0 = mu0`, limits
`mu0 +/- L sigma sqrt(lambda / (2 - lambda) (1 - (1 - lambda)^(2i)))`, defaults lambda 0.2, L 3.

CUSUM (tabular, two sided, standardised): `C+_i = max(0, C+_{i-1} + z_i - k)`,
`C-_i = max(0, C-_{i-1} - z_i - k)`, alarm when either exceeds h, defaults k 0.5, h 5.

Change point: single least-squares split of the mean (first step of binary
segmentation); the split maximises `S_tau^2 / (tau (T - tau))` where `S_tau` is the
cumulative sum of deviations from the overall mean. A hinge model
`a + b max(0, t - tau)` is fitted the same way; the lower SSE decides between
`shift` and `drift`.

Drift summary per station and metric: daily means of production units, baseline = first
third of the days, sigma of a daily mean = pooled within-day sd / sqrt(n). A series is
flagged when CUSUM or EWMA alarms and the mean of the last `max(5, days/10)` days sits at
least 2 sigma from the baseline mean. Alarms below that size are shown but not flagged.

Agreement: Pearson r, bias = mean(station - reference), limits of agreement = bias +/-
1.96 sd(diff), least-squares slope and intercept of the station against the lab
reference station (STA-12), all on the 30 golden units measured at every station.

## Metrics (synthetic definitions)

| Metric | Unit | Target | LSL | USL | Plausible range |
| --- | --- | --- | --- | --- | --- |
| luminance_nits | nits | 500 | 450 | 550 | 0 to 5000 |
| color_delta_e | dE2000 | 1.5 | 0 | 3.0 | 0 to 100 |
| mtf_50 | cycles/pixel | 0.55 | 0.45 | 0.70 | 0 to 1 |
| binocular_misalignment_arcmin | arcmin | 2.0 | 0 | 5.0 | 0 to 60 |

Twelve stations: STA-01 to STA-05 at contract manufacturer site A, STA-06 to STA-10 at
site B, STA-11 and STA-12 in the lab, STA-12 being the reference. Each station has one
instrument listed in `data/instruments.csv`.

## Limitations

- Synthetic data only, from one generator with Gaussian noise; real test lines have
  structure this does not model (lot effects, fixtures, rework, retest loops).
- One process type and one set of spec limits; no handling of one-sided specs beyond
  a zero lower bound.
- SQLite in a single file; no concurrency, no partitioning, no access control.
- No scheduler: `alerts` writes a file and nothing delivers it.
- No real instruments, no calibration certificates, no traceability chain; the register
  is a CSV.
- Gauge R&R assumes a balanced crossed design and never pools the interaction term.
- The flag rule (alarm plus 2 sigma current offset) is a pragmatic heuristic, not a
  tuned detector; its false alarm rate was checked on a handful of seeds, not derived.
- No optics expertise is claimed; metric names are illustrative.

## Reproduce and explain before using on a resume

Run `python -m pytest -q` and `python -m station_analytics demo --check` yourself and
read the output. Then make sure you can explain, without notes: how the ANOVA variance
components are computed and why the interaction term matters; the difference between
Cp, Cpk and Ppk; why station names are canonicalised at ingest and never in the report;
why unknown columns are quarantined rather than dropped; what makes the batch load
idempotent; what the reconciliation check proves and what it does not. The
`LEARNING_GUIDE.md` file lists these questions with short answers. If you cannot answer
them in your own words, do not put this project on a resume yet.
